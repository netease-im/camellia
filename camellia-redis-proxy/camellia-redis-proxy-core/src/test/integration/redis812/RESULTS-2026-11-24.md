## 发现并修复的问题

`ZADD key score member` 在 converter 中被转换两次：先进入四参数专用分支，再进入通用分支。使用非幂等前缀 converter 时，Redis 存入 `v:v:member`，之后 `BZMOVE` 只逆转换一次，返回 `v:member`。

这是历史问题：`2021-08-11` 的提交 `accfa159ae` 已包含这两个独立的 `if` 分支，本批新增命令没有引入该问题。

已删除重复的专用分支，保留通用解析，使每个 member 只转换一次。增加了单 member 和带选项的多 member 回归断言；36 项相关单元测试通过。修复后真实的单实例/集群 `BZMOVE`、嵌套返回值和后端编码检查通过。

阻塞验证等待 `CLIENT LIST` 中匹配命令的客户端出现 `b` 标记，再执行唤醒写入，避免将上一次普通读取误认为已阻塞而产生测试竞态。

## 构建兼容说明

- 构建工具 GNU Make 4.4.1 和模块源码位于临时目录；临时构建副本跳过了与编译无关的 shell profile 初始化。
- TimeSeries 使用 macOS SDK 的 C++ 头文件和 C++17 编译。
- ReJSON 基于 8.12.0 源码，临时依赖锁使用 `home 0.5.11`、`time 0.3.44`，并将 ijson 中的新式 `str::from_utf8_unchecked` 调用写为等价的 `std::str::from_utf8_unchecked`，以兼容 Rust 1.85.1。没有修改 JSON 命令实现；这属于源码构建验证，不是官方预编译发行包验证。
- 为 Search 构建安装了 OpenSSL 4.1.0；Homebrew 同时更新了 ca-certificates。没有切换默认 JDK/Rust 版本。
